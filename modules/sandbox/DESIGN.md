# claude-sandbox: design

A nix-darwin module that runs Claude Code agents isolated from their owner:
each agent is its own macOS user, runs inside a Seatbelt profile, and reaches
the network only through its own filtering proxy. It is meant as a plugin
other people can use, so every choice below is an option with a safe default.

## Layers

Two independent barriers, so a hole in one doesn't expose the owner:

1. **The OS user.** Each agent is `_claude_<name>` with a `0700` home. The
   owner's home (`/Users/<owner>`, `0750` by default) is closed to it.
2. **Seatbelt** (`claude-sandbox.sb`, SBPL version 3). Default-deny: the agent
   reads the system, its own home and its workspace; writes only its workspace,
   its tmp and Claude Code's state; talks only to its proxy.

Plus the **proxy**: one tinyproxy per agent on `127.0.0.1:<port>`, with a
domain allowlist, `CONNECT` to 443 only, default deny.

## Options (per agent)

```nix
services.claude-sandbox.agents.<name> = {
  uid = 600;
  proxy.port = 8801;
  proxy.allowedDomains = [ "^(.*\\.)?anthropic\\.com$" ];

  workspace = {
    mode = "clone";           # "clone" (default) | "in-place"
    allowCommit = true;       # clone mode only
  };

  read = {
    paths = [ ];              # fixed read grants on the owner's files
    allowRuntimeGrants = true;  # `claude-<name> --read <path>`
  };

  homeReadScope = "full";     # "full" (default) | "state-only"
};
```

### `workspace.mode`

- **`clone`** (default). The wrapper clones (or adds a worktree of) the
  project into the agent's home, and the agent works there. Work comes back
  through git: the owner fetches from the agent's clone. The owner's home gets
  no ACLs, and the agent's user has no access to anything of the owner's, so
  the two layers are truly independent.
- **`in-place`**. The agent works in the owner's tree, for working on the same
  tree at the same time. The wrapper must grant the agent `search` (traverse,
  not list) on every directory above the workspace, plus access inside it, and
  remove both on exit (the lockfile mechanism). Cost: the owner's home carries
  ACLs, and an agent can open any file there it can name and that is readable
  by others; Seatbelt becomes the only barrier.

Why `clone` is the default: tested on arrakis, another user can't even list
`/Users/pplanel` (`0750`), so an ACL on the workspace alone doesn't work, and
opening the path up weakens the OS layer for the whole home.

### `workspace.allowCommit`

In `in-place` mode, `.git` is write-denied whole (see the bypass below): its
hooks would run as the owner. In `clone` mode the clone belongs to the agent,
its hooks run as the agent, and the owner only fetches, so committing can be
allowed. Default `true` there.

### `read.paths` and `--read`

The owner's files are invisible by default. A grant opens one path, read-only:
fixed in config (`paths`), or for one session (`--read <path>`). A grant
adds both an ACL (`search` on the parents, read inside) and a Seatbelt
`(allow file-read* (subpath …))`, removed when the session ends. Every
exception is visible and typed by the owner, rather than opening the home.

### `homeReadScope`

The home is the agent's own, so it reads all of it (`full`). In `clone` mode
the home holds every workspace of that agent, so one session can read another
project's clone of the same agent. `state-only` limits reads to Claude Code's
state (`.claude`, `.claude.json`, caches) plus the workspace. For real
separation between projects, use one agent per project.

## Profile generation

`claude-sandbox.sb` is the base. Mode-dependent parts are generated by Nix and
appended: the `.git` deny (in-place, or clone without commit), `--read`
grants, the home read scope. The base needs every `-D` parameter, or it
doesn't compile; that fails closed (no proxy port, no agent).

## What the tests taught (SBPL)

Tested with `sandbox-exec` on macOS 26, watching denials with
`log stream --predicate 'sender == "Sandbox"'`.

- `#` is not a comment; `;` is. One `# vim:` line kept the profile from loading.
- Seatbelt matches **resolved** paths. `/tmp/x` is `/private/tmp/x`; a rule
  on `/tmp/...` never matches. Every `-D` path must be resolved (`pwd -P`,
  `/private/tmp`, `realpath`). Symlinked system paths too:
  `/System/Cryptexes/OS` is really `/System/Volumes/Preboot/Cryptexes/OS`.
- Rules match **each operation's own path**. A deny on `.git/hooks` was
  bypassed with `mv .git .gitx`, write `.gitx/hooks/pre-commit`,
  `mv .gitx .git`. Deny the whole directory (`subpath .git`) instead.
  Renaming onto a denied file name is denied (the destination is checked).
- Version 3 default-denies what version 1 left open. Needed so far:
  `syscall-unix`, `syscall-mach`, `file-test-existence`, `system-fcntl`,
  `system-mac-syscall` (AMFI, Sandbox), `socket-option-get/set`,
  `file-map-executable` on `/nix/store` (nix binaries load store dylibs), and
  the `security.mac.lockdown_mode_state` sysctl. Syscalls and fcntl are
  allowed whole for now; narrowing them is future work.
- SBPL takes one port or `*` in network addresses, not a range.
- `(param "X")` without `-D X=` fails to compile.
- Claude Code is Bun (JavaScriptCore) and needs JIT
  (`dynamic-code-generation`). Denying it adds nothing: the agent can already
  write and run binaries.
- The process changes names (`sandbox-exec` → `bash` → `claude` →
  `.claude-wrapped`); log filters must include all of them.
- `localhost:*` outbound reached claude-mesh (127.0.0.1:7480, unauthenticated)
  and every other local service. DNS through mDNSResponder is an exfiltration
  channel, and with a proxy the client doesn't need it. Both are closed;
  outbound is the proxy port only.

## Wrapper requirements

- `HOME`, `USER`, `TMPDIR` set to the agent's; `env -i` otherwise.
- `HTTP(S)_PROXY` pointing at the agent's proxy (nothing else gets out).
- All `-D` paths resolved; the session tmp under `/private/tmp`, not `/tmp`.
- Secrets never on a command line (see open items).

## Open items

1. **The API key is visible in `ps`** (fixed). The wrapper
   passes `ANTHROPIC_API_KEY=…` as an argument to `sudo … env -i`; `sudo`
   stays alive, as root, for the whole session. Tested with a fake key:
   `nobody` reads it with `ps -axww`, so does any unsandboxed process of any
   user. From inside the sandbox it is denied, by
   `(allow process-info* (target same-sandbox))`: a direct
   `sysctl KERN_PROCARGS2` gets `process-info-pidinfo others`. Fix: never put
   the key on a command line. The wrapper writes it to a `0600` file in the
   agent's session tmp, and the agent's Claude Code settings point
   `apiKeyHelper` at it. Preferred over `env_keep`, which would leave the key
   in the environment every subprocess inherits. Passed as
   `--settings '{"apiKeyHelper":"/bin/cat <file>"}'`. Side effect (tested
   with a fake key): on a 401 Claude Code calls the helper again and retries
   with backoff, silently and without end, so a revoked key hangs the agent
   instead of failing.
2. **Session tmp unresolved** (fixed). `mktemp -d /tmp/claude-…` yielded
   `/tmp/…`, so the agent couldn't write its own tmp. Now `/private/tmp`.
3. **Claude Code version** (fixed). The module used `pkgs.claude-code` from
   nixpkgs-unstable. It now lives in the root flake as
   `darwinModules.sandbox`, with a `services.claude-sandbox.package` option
   defaulting to the version claude-code-nix pins.
4. The `.config` read deny (meant for the owner's `~/.config`) also matches
   the agent's own `~/.config`.
5. The `hkdf-derived` strategy uses AES-CBC with a zero IV.
6. `/tmp/.claude-acl-locks` can be pre-created by another user (in-place mode).
7. Secure Enclave keys work only in the context that created them (login
   session vs daemon), and `any-biometry` blocks anything unattended.
8. End-to-end test not done yet: a real tinyproxy and `claude` reaching the
   API through it.
